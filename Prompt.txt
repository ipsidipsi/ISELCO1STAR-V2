## ?? Ticket Lifecycle Implementation

### **Status Flow**
```
NEW ? SEEN ? ASSIGNED ? IN_PROGRESS ? RESOLVED ? CLOSED
                ?                          ?
            (Reopen) ???????????????????????
Transition Rules
1. NEW ? SEEN: Auto-triggered when ticket opened by any department user
2. SEEN ? ASSIGNED: When admin/user accepts ticket or admin assigns
3. ASSIGNED ? IN_PROGRESS: Fixer clicks "Start Working"
4. IN_PROGRESS ? RESOLVED: Fixer clicks "Mark Resolved" (requires solution note + optional photo)
5. RESOLVED ? CLOSED: Creator verifies and approves
6. RESOLVED ? IN_PROGRESS: Creator rejects and provides feedback
7. CLOSED ? REOPENED: Creator can reopen within configurable timeframe


Timeline Tracking
Each status change stores:
* Timestamp
* User who triggered change
* Optional notes/reason
* Display as visual timeline in both mobile and web UI

?? Role-Based Access Control (RBAC)
Role Hierarchy
1. Superadmin
* Full system access
* Manage all departments, users, roles, permissions
* View all tickets across departments
* Configure categories, priorities, system settings
* Suspend/activate accounts
* Password reset capabilities
* Assign department admins
2. Department Admin
* Manage users within assigned department(s)
* View all tickets in their department(s)
* Assign tickets to department users
* Approve/reject ticket resolutions
* Cannot modify system-level settings
3. User (Default Role)
* Create tickets
* View own created tickets
* View assigned tickets
* Accept open department tickets
* Update ticket status when assigned
* Chat on involved tickets
4. Custom Roles
* Superadmin can create custom roles
* Granular permission assignment
* Examples: "Viewer Only", "Reporter", "Admin" Can also assigned departments that can be handled by each admin 
ex etsd manager can supervise ETSD dept only
FInance manager can supervise ,FINANCE,AUDIT department
General Manager can supervise All dept

?? Security Requirements
Authentication
* Laravel Sanctum SPA authentication
* Mobile: Token-based (sanctum:auth middleware)
* Session timeout: 5 min of inactivity (configurable)
* Forgot password on normal users
forgot password for normal users will be treated as new “special ticket” for department admin/superadmin only
the special ticket has a button “reset password” button once clicked will make the user
admin has user management dashboard and can reset password
This is a ticket-based password reset system (not automated email):
User clicks "Forgot Password?" on login page
Modal appears requesting verification details:
Username (must exist)
First Name
Last Name
Department
Mobile Number
System validates username exists
Ticket is created with:
Title: 
PASSWORD RESET for {username}, {name}, {mobile} [SUPERADMIN ONLY]
Priority: High
Category: Account/Access
Department: IT/department admin
Status: New
Department admins are notified via in-app notification
User sees success message and modal closes
Admin manually resets password via User Management or reset button in the ticket details password is “1234”
User logs in with “1234” and is forced to change password (new password must not be “1234”
